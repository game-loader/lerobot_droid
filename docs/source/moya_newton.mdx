# Moya Newton Charger Grasp

Moya Newton is a fused, GPU-batched charger-grasp simulator used by this
checkout for state-only Diffusion Policy training and evaluation. The LeRobot
adapter runs the native vector environment directly: one simulator instance
owns all worlds and one CUDA context.

<Tip warning={true}>
  The pinned Moya repository and its robot and charger assets do not contain a
  tracked license file. Treat this integration as internal until the upstream
  license and redistribution terms are clarified.
</Tip>

## Installation

Initialize the pinned submodule and sync the runtime extras into the
repository-local `.venv`:

```bash
git submodule update --init --recursive

UV_CACHE_DIR=.uv-cache UV_PROJECT_ENVIRONMENT=.venv uv sync \
  --locked \
  --no-dev \
  --extra training \
  --extra diffusion \
  --extra moya_newton
```

The submodule URL uses GitLab SSH. The machine running the initialization
command must have access to `git@gitlab.com:game-loader/moya_newton.git`.

The integration pins Newton 1.3.0 and Warp 1.14.0. It requires Linux and an
NVIDIA CUDA device for normal evaluation. It is headless and does not create a
Newton viewer.

## Environment contract

Use `--env.type=moya_newton`. The default `randomized_grasp_v1` preset matches
the scene, controller, and data encoding used to collect the local 100-episode
LeRobot v3 dataset:

| Property                 | Value                                                              |
| ------------------------ | ------------------------------------------------------------------ |
| Observation              | `observation.state`, 39D float32                                   |
| Action                   | Raw policy action, 14D float32                                     |
| Frequency                | 60 Hz                                                              |
| Evaluation horizon       | 930 policy steps                                                   |
| Simulation substeps      | 8                                                                  |
| Charger spawn center     | `(0.37, 0.00, 1.095)` m                                            |
| Charger XY randomization | Independent uniform 3 cm square                                    |
| Charger mass             | 0.5 kg                                                             |
| Contract schema          | 14                                                                 |
| Contract SHA-256         | `a06cb5e5a51c3b53a1972e77d803a15c0916395f9c15ecd7172433cc1e6c293e` |

Environment creation fails if the live contract does not match this hash. The
adapter passes postprocessed 14D actions to Moya unchanged; Moya applies its
translation, rotation, and hand-control rules internally.

Each dataset trajectory contains 930 recorded state-action frames. The
collection script gave its backend an additional 8-step termination margin so
the fixed 930-step scripted rollout could finish without SAME_STEP autoreset;
the LeRobot evaluation horizon is the recorded 930 policy steps.

## Success metric

LeRobot's `pc_success` requires every condition below at the terminal step:

- a true grasp was established for 20 consecutive steps at some point;
- the charger was lifted at least 5 mm with no table contact after that grasp;
- final charger lift is at least 15 mm;
- final table contacts are zero; and
- final hand-to-charger contacts are positive.

Moya's stricter native success value remains available as `native_success`, but
it does not drive `pc_success`. The 15 mm terminal threshold is intentionally
stricter than the original 5 mm dataset filter. In the verified collection's
adjacent `collection_summary.json`, 94 of the 100 accepted demonstrations
satisfy it. The source artifact is
`randomized_grasp_100_20260813-230331/collection_summary.json` with SHA-256
`f1f6e73a2a7e5a7228fdb1ce5f5f867b4a36168b962351c1d891c7409c866d6c`.

## Evaluation

Run a state-only Diffusion checkpoint with the native 16-world batch:

```bash
UV_CACHE_DIR=.uv-cache UV_PROJECT_ENVIRONMENT=.venv uv run lerobot-eval \
  --policy.path=/path/to/pretrained_model \
  --env.type=moya_newton \
  --env.device=cuda:0 \
  --eval.batch_size=16 \
  --eval.n_episodes=16 \
  --eval.use_async_envs=false \
  --policy.device=cuda
```

The environment ignores an accidental `use_async_envs=true` request with a
warning because it already owns the fused batch. Specify the batch size
explicitly; the generic CPU-based auto-tuning default can create more CUDA
worlds than intended.

Evaluation is state-only and never records videos. Standalone `lerobot-eval`
and training-time evaluation automatically request zero rendered episodes for
this environment.

## Reproducibility

Moya currently owns one NumPy random generator for the full fused batch.
LeRobot's list of per-world seeds is deterministically folded into one batch
seed. Results are reproducible for the same seed list and batch size, but an
individual world is not guaranteed to keep the same initial state when the
batch size changes.

## Troubleshooting

- Missing `moya_batched_env.py`: run
  `git submodule update --init --recursive`.
- Missing `newton` or `warp`: sync the `moya_newton` extra shown above.
- Contract mismatch: start a fresh Python process without another Moya checkout
  on `PYTHONPATH`, then verify the submodule revision with
  `git submodule status`.
- CUDA or Warp cache errors: verify the NVIDIA driver is visible and point
  `WARP_CACHE_PATH` to a writable directory if the default user cache is not
  writable.
